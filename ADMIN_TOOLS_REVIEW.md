# Проверка инструментов администратора

Дата: 2026-09-08. Проверяется текущий код, а не предполагаемые возможности.

## Вывод

Основные рабочие разделы уже существуют. Главная проблема: перегрузка страницы
проекта и отдельные действия, которые не соответствуют своей подписи.
Удалять целые модули на основании этой проверки не требуется.

## Что полезно и сохранено

| Инструмент | Назначение | Где проверен |
| --- | --- | --- |
| Объекты, двери, этажи, позиции | Контроль состава и выполнения монтажа | `src/views/ProjectsPage.tsx` |
| Импорт Excel и отчёт ошибок | Загрузка дверей без ручного ввода; исправление ошибочных строк | `src/views/ProjectsPage.tsx` |
| Массовое назначение | Передача выбранных дверей монтажнику | `src/views/ProjectsPage.tsx` |

| Операции и настройки | Ошибки отправки, импорта, синхронизации и настройка интеграций | `src/views/OperationsPage.tsx`, `src/views/SettingsPage.tsx` |

Справочники и система уже сгруппированы в сворачиваемых разделах боковой панели.
Технические инструменты полезны при сбоях, но не должны занимать ежедневный рабочий экран.
Наличие кода отправки документов не доказывает настройку реального почтового сервиса.

## Исправления этого шага

- Вместо обманчивого «+ фильтр», сбрасывавшего фильтры, показан явный сброс.
- Поиск дверей учитывает маркировку, позицию и номер квартиры.
- Добавлен фильтр назначений: все монтажники, без назначения, конкретный исполнитель.
- Скрытые фильтрами выбранные двери показаны отдельным счётчиком; их можно снять с выделения.
- «Матрица» и «Таблица» переходят к соответствующим рабочим областям с передачей фокуса.
- «Активность», открывавшая только импорты, переименована в «Историю импорта».
- Статусы в фильтрах используют существующие переводы, значения API не меняются.
- Роль VIEWER больше не получает ссылку «Создать проект»; просмотр объектов сохранён.
- Дата и «ещё» в месячном календаре открывают точный день, включая скрытые события.
- Переход к дню сохраняет фильтры и позволяет открыть карточку события.

## Что остаётся улучшить

1. Разделить длинный экран проекта на рабочие области без дублирования матрицы и реестра.
   Делать отдельно, с сохранением ссылок, выделения и незавершённых форм.
2. Отделить настройку шаблонов документов от повседневного формирования готовых файлов.
3. Упростить технические формулировки центра операций; сохранить повторы отправки и диагностику.
4. Проверить нестабильную первую загрузку API: в браузере наблюдался `Failed to fetch`,
   повтор входа и загрузки помог. `/health` и CORS preflight отвечали успешно.
   9 сентября API восстановлен, обработка временных сбоев авторизации исправлена
   (см. ниже). Причина всех прежних сетевых ошибок не установлена. В реестре также
   наблюдался UUID типа двери вместо названия; обработка справочников исправлена
   следующим шагом ниже. Нестабильный запрос с записью 200 ещё требует наблюдения.

## Продолжение: ошибки API и справочники проектов, 2026-09-09

- Подтверждён дефект в backend `app/main.py`: middleware диагностики формировал
  безопасный ответ 500 снаружи CORS. Браузер разрешённой админки не мог прочитать
  этот ответ. Регрессионный тест сначала упал на отсутствующем заголовке, затем
  прошёл после исправления порядка middleware. Разрешённые источники не расширены.
- `X-Request-ID` доступен браузеру для сопоставления ответа с журналом API.
  Внутренние подробности ошибок по-прежнему не попадают в ответ.
  13 тестов CORS и observability прошли. Backend-коммит: `697a1d0` (GitHub).
- `src/hooks/use-reference-list.ts` объединяет существующую загрузку шести
  списков: типы дверей, каталог изделий, монтажники, причины, доп. работы и шаблоны.
  Ошибка отделена от пустого списка, последний успешный результат сохраняется
  с предупреждением. При 401/403 данные очищаются. Устаревшие запросы отменяются.
- `src/views/ProjectsPage.tsx` использует существующий `DataStateNotice` для
  адресного повтора. Повтор одного справочника не перезагружает объект, не снимает
  выделение дверей и не сбрасывает поиск. Ошибка типов больше не затирается загрузкой раскладки.
- Создание двери, назначение, выбор причины и формирование документа не используют
  недоступный соответствующий справочник. Просмотр последнего загруженного списка сохранён.
- Вместо UUID при сбое показано «Тип недоступен». Типы загружаются постранично,
  включая неактивные для названий существующих дверей; в новом импорте доступны
  только активные типы. Неполный справочник не публикуется как успешно загруженный.
- 51 frontend-тест прошёл: хук справочников и весь набор ProjectsPage, включая
  импорт, назначение, создание дверей, права и восстановление после ошибки.
- ESLint изменённых файлов и production-сборка с TypeScript прошли, сформированы
  24 страницы. API перезапущен с проверенным исправлением, `/ready` отвечает 200.
- Прямой авторизованный GET списка объектов вернул 200, корректный JSON и
  CORS-заголовок для админки. Временная refresh-сессия этой проверки отозвана.
- В браузере проверен существующий объект с 580 дверями: первый переход, названия
  типов, наличие монтажника в назначениях, поиск по позиции и полный reload.
  После reload в реестре снова 580 строк и нет alerts. Поиск возвращён в пустое
  состояние. Ошибки первой загрузки в этом прогоне не воспроизвелись.
- Двери, назначения, начисления и документы в рабочей базе не изменялись.
- Изменения не требуют миграции: схема БД и API-контракты сохранены.
  Причина прежнего сетевого сбоя при записи 200 в журнале не доказана этим
  исправлением. Не следует объявлять все ошибки первой загрузки устранёнными.

## Продолжение: доступность и авторизация, 2026-09-09

- API, PostgreSQL и MinIO были остановлены одновременно, без restart policy.
  Docker не сообщил OOM. Причина исходной остановки не установлена.
- В workspace Compose для этих трёх сервисов добавлен `restart: unless-stopped`.
  Политика применена к существующим контейнерам, сервисы запущены без пересоздания
  томов. `/ready` подтверждает доступность БД. Контейнер админки не запускался:
  используется локальная сборка, чтобы не поднимать второй frontend.
- `src/lib/api.ts`: временные ошибки сети, 429 и 5xx при refresh больше не удаляют
  локальную сессию. Отклонённый refresh (401/403) по-прежнему завершает её.
  Повреждённый ответ refresh не сохраняется. Нет автоматического повтора записи
  после сетевой ошибки: это могло бы дублировать выполненную операцию.
- Исправлена блокировка повторного refresh после запроса без refresh-токена.
  Параллельные запросы используют один refresh; поздний ответ не восстанавливает
  вышедшую или заменённую сессию.
- `src/components/RequireAuth.tsx`: при временной ошибке защищённое содержимое
  скрыто, доступна явная повторная проверка без перехода на login. Доступ проверяется
  заново при смене маршрута или области роли. Проверки прав не ослаблены.
- Сообщения о потере связи и недоступности refresh переведены на RU/EN/HE.
- Прошли 59 сценариев в пяти наборах: API, сообщения об ошибках, права,
  RequireAuth и форма входа. Первый объединённый запуск не смог запустить один
  worker вовремя; отдельный повтор RequireAuth прошёл, настройки тайм-аутов не менялись.
- TypeScript (`--noEmit --incremental false`), ESLint изменённых файлов и
  `npm run build` прошли. Собраны 24 страницы; standalone-сервер отвечает на
  `http://localhost:5173`, API `/ready` возвращает `database: ready`.
- В браузере подтверждены вход, переход к объектам, повтор их загрузки без
  повторного входа, переход к календарю и восстановление сессии после reload.
  Календарь проверен визуально. Бизнес-записи не создавались и не изменялись.
- При первой загрузке объектов сетевой сбой воспроизвёлся даже при ответе 200
  в журнале API; явный повтор помог. Значит, проблему первого запроса нельзя
  считать закрытой. Следующая диагностика должна отделить доставку ответа в
  браузер от ошибок API и исправить отображение сбоев загрузки справочников.
- Это не полный backend/mobile release-прогон и не доказательство настройки
  production-инфраструктуры. Схема БД, начисления и бизнес-операции не менялись.

## Результаты проверки

- 45 затронутых сценариев проектов, календаря и меню прошли с учётом повторного
  прогона исправленного теста. Проверены поиск, назначения, скрытое выделение,
  смена проекта, импорт, роли и раскрытие дня с пятью событиями.
- TypeScript без генерации файлов, ESLint изменённых файлов и production-сборка прошли.
- Сборка сформировала 24 страницы. Рабочая админка: `http://localhost:5173`.
- В браузере на объекте с 580 дверями проверены поиск по позиции, назначения,
  сброс и переход к реестру. Реальные двери и назначения не изменялись.
- В браузере проверен переход из месяца на 15 сентября 2026 года; календарь
  просмотрен на ширине 1280 и 390 px. Временный размер окна сброшен.
- Реальные события для тестирования переполненного дня не создавались:
  раскрытие «ещё» и карточки пятого события проверено регрессионным тестом.

## Границы проверки

Углублённые изменения и регрессионные тесты: проекты, календарь, боковая панель.
Остальные разделы проверены на назначение инструментов по навигации и коду интерфейса.
Это не полный аудит backend, расчёта зарплат, доставки писем или мобильной синхронизации.
Схема базы, API, расценки и рабочие данные этим шагом не изменяются.
